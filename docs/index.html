Quarto-glossary

This extension provides a shortcode for defining terms and building glossaries in Quarto. It is a fork of debruine/quarto-glossary that also works in PDF and Word, and adds grouped glossary files, aliases and glossary tables. See the changelog for what changed.

Setup

Installing

quarto add MitchellAcoustics/quarto-glossary

This will install the extension under the _extensions subdirectory. If you’re using version control, you will want to check in this directory. It needs Quarto 1.4.0 or later.

Glossary file

You can store definitions in a YAML file. Use markdown to create paragraphs, links, and lists. Make sure each new line in a definition is indented two spaces (sorry YAML is a bit picky, but it’s the best human-editable solution).

SESOI: |
  Smallest Effect Size of Interest: the smallest effect that is theoretically or practically meaningful

  See [Equivalence Testing for Psychological Research](https://doi.org/10.1177/2515245918770963) for a tutorial on methods for choosing an SESOI.
p-value: |
  The probability of the observed data, or more extreme data, if the null hypothesis is true. The lower the p-value, the higher the test statistic, and less likely it is to observe the data if the null hypothesis is true.

Grouping terms

Terms can be grouped under a heading by nesting them one level deep. Terms that aren’t under a group can sit alongside the groups.

html: |
  An ungrouped term.

Hypothesis testing:
  alpha: |
    The threshold chosen in Neyman-Pearson hypothesis testing...
  p-value: |
    The probability of the observed data...

Group names are not terms themselves, and grouping doesn’t change how you use a term: {{< glossary alpha >}} works whichever group alpha is in. Only one level of grouping is supported.

Aliases

A term can have other names, such as synonyms or abbreviations, that mean the same thing. Write the term as a mapping with a definition and a list of aliases (a single alias can be written without the list):

Hypothesis testing:
  alpha:
    definition: |
      The threshold chosen in Neyman-Pearson hypothesis testing...
    aliases: [alpha level, significance level]

Using an alias in the text gives the same definition as the term, in popups, with definition=true and in nonhtml="footnote" (where the term and its aliases share one footnote). In tables and lists the term is listed once, with an “Also: …” line in smaller text, and alphabetical sorting uses the term, not its aliases.

{{< glossary "significance level" >}}

An entry is a term if it is a mapping with a definition, and a group if it is a mapping without one, so definition and aliases can’t be used as term names. An alias that is already the name of a term, or an alias of an earlier term, is ignored with a warning: the term keeps it. A mapping without definition inside a group is read as a term with a nested definition and gives a warning, because only one level of grouping is supported.

Duplicate terms

Terms are looked up by name alone, so use each term name only once across all groups. If a term is defined more than once with different wording, the first definition in the file is used for popups and definition=true, and the extension logs one warning for that term.

Defaults

In the YAML header of your document, or the _quarto.yml file for your book or website, add the following defaults:

glossary:
  path: glossary.yml
  popup: click

Set path to the path to your glossary YAML file, and popup to “click”, “hover”, or “none”. You can change these defaults for any individual inline glossary item.

Examples

The simplest use starts with the word glossary and then the term to be defined. Click on the underlined word to see a pop-up definition.

{{< glossary power >}}

Display

No need to change if you’re just using different case:

{{< glossary Power >}}

Use quotes if your term is more than one word.

{{< glossary "effect size" >}}

Add a display argument if you want to display something different than the term:

{{< glossary alpha display="alpha criterion" >}}

Popups

The “click” option shows a styled popup when the term is clicked. This site sets it as the default in its _quarto.yml, and the package default is “hover”.

{{< glossary alpha popup="click" >}}

The “hover” option uses the web browser’s built-in tooltip, which shows plain text only. You can wrap the term in a link, which opens when it is clicked.

[{{< glossary alpha popup="hover" >}}](https://psyteachr.github.io/glossary/a#alpha)

Set popup to “none” to mark a term without a popup.

{{< glossary alpha popup="none" >}}

Definitions

If you need to include a definition for a term that is not in the glossary file or is different from the one in the glossary file, you can set the def argument.

{{< glossary quarto def="An open-source scientific and technical publishing system" >}}

Reuse a definition in the text

Set definition=true to insert a term’s definition from the glossary file as text, in any format. This keeps body text and glossary wording in step. A definition with several paragraphs is joined into one run of text, and an unknown term gives a warning and inserts nothing.

{{< glossary SESOI definition=true >}}

Smallest Effect Size of Interest: the smallest effect that is theoretically or practically meaningful
See Equivalence Testing for Psychological Research for a tutorial on methods for choosing an SESOI.

PDF and other formats

Popups only work in HTML. In other formats, such as PDF and Word, the nonhtml option controls how a glossary term appears:

nonhtml Result
"text" The display text alone.
"link" The display text, linked to the section given by the link option, for example a chapter of a book that holds the glossary table.
"footnote" The display text, with the definition as a footnote on the term’s first use in the document.

The default is "link" if link is set, and "text" otherwise.

glossary:
  path: glossary.yml
  link: "#sec-glossary"

Both options can also be set on a single term. In HTML these examples are normal popups; in PDF the first links to the Table section below, and the second gets a footnote on its first use but not on its second.

{{< glossary power link="#table" >}}

{{< glossary p-value nonhtml="footnote" >}}

, and again: .

A term that isn’t in the glossary file gets no footnote unless you give it a def, which is then used for the note. In a book, each chapter is its own document, so a term is footnoted once per chapter. An unrecognised value gives a warning and uses the default.

Table

Set table=true to get a table of every term in the glossary file. It works in any format, keeps term case and Markdown formatting from the file, and lists terms in the order they are written in the file. If the file is grouped, each group gets a shaded band row naming it, with ungrouped terms first.

{{< glossary table=true >}}

Order

sort is "file" (the default, the order written in the glossary file) or "alpha". Alphabetical sorting ignores case. In a grouped table the group names are sorted first, then the terms within each group, with ungrouped terms staying at the top. In a flat table all the terms are sorted together.

{{< glossary table=true sort="alpha" >}}

layout and sort can also be set as defaults under glossary: in your _quarto.yml. An invalid value gives a warning and uses the default.

Table styling

In HTML the table uses Bootstrap’s striped table style, and band rows have the glossary-group class, which you can restyle with the CSS variables --glossary-group-bg and --glossary-group-color.

In PDF the bands are shaded with the glossarygroup colour (light grey by default). Shading needs xcolor’s table option; with Quarto’s default template, turn it on with classoption: [table] under format: pdf:. Without it the document still builds and the bands are unshaded. To change the colour, add \colorlet{glossarygroup}{gray!25} to include-in-header. The extension leaves row striping and padding in PDF to you, because it would affect every table in your document; the README has a recipe.

Options reference

Option Values What it does
path file path (default glossary.yml) The glossary file.
popup "hover" (default), "click", "none" HTML only.
display text Show different text from the term.
def text Use this definition instead of the file’s.
link "#section" Non-HTML formats: link every term to this section.
nonhtml "text", "link", "footnote" Non-HTML formats: how a term appears.
definition true Insert the term’s definition as text.
table true Insert the glossary as a table (or list).
groups "A, B, ungrouped" With table: only these groups.
layout "grouped" (default), "flat", "list" With table: how to lay it out.
sort "file" (default), "alpha" With table: file order or alphabetical.
